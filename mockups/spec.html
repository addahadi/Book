Product & Build Spec · v1 locked

Reading Stage

Physical books beat digital ones for thinking, not for looking. So we won't fake paper — we'll close the specific deficits that make PDF reading worse than a real book, built around annotation and sense of place.

Platform Web, local-only Stack React · TS · pdfjs-dist For serious readers of dense books Date 2026-08-17

01 The four deficits

Ranked. Everything we build serves these in order — and nothing else.

1

Annotation & marginalia the core

Marking up dense text and finding those marks again.

2

Spatial memory & sense of place the wedge

Knowing where you are, and where a passage lived.

3

Focus & distraction

A book has no tabs, notifications, or upsells.

4

Eye comfort

Pagination and a warm night mode, not screen glare.

02 Non-goals

Written down on purpose — the fastest way to never ship is to quietly build these.

  • Not an editor. No form-filling, page manipulation, or signing.
  • Not chasing market share. Real users who love it > beating MarginNote.
  • No tactile realism. No page-curl, no fake paper grain.
  • No OCR in v1. Born-digital PDFs; scanned books degrade gracefully.
  • No gamification in v1. Deferred, not rejected — reading isn't a metrics game.
  • No backend / accounts in v1. Fully local. Sync comes later.
  • No knowledge-graph in v1. Notes are objects, but no linking or tags yet.

04 Feature specification

v1 scope, by area. Tap to expand.

▶📖 Reading surface
  • Paginated by default — pages turn (replace), never scroll. Scroll is a hidden toggle only.
  • Layouts: two-page spread on wide screens, single page on narrow / tablet.
  • Turn controls: ← / → keys, edge click/tap, buttons, swipe.
  • Sense of place: a two-hands indicator (behind you / ahead) + "page N of M · P% in".
  • Night mode: real warm dark theme. Auto-resume: reopen exactly where you stopped.
▶📚 Library & persistence
  • Full bookshelf in IndexedDB — PDF bytes stored locally; shelf always there, offline, every browser.
  • Content-hash identity so annotations always re-bind to the right book.
  • Drag-and-drop ingest, remove-from-library control.
  • Export / import annotations as the safety valve against cleared storage.
▶✍️ Annotation — the core
  • Highlight (multi-colour), underline / strikethrough, margin note, bookmark / dog-ear.
  • Stored as a sidecar — the PDF is never rewritten.
  • Born-digital text only. Scanned fallback: bookmarks + region-box highlights, with a clear notice.
▶🗂️ Notes as objects + notebook
  • Every mark is a first-class object with a stable ID and its own detail page (excerpt, note, metadata, go-to-source).
  • Notebook panel: all marks in reading order, click-to-jump, filter by colour.
  • Data model reserves tags and links — v1 builds neither.
▶🧭 Navigation
  • Embedded TOC, full-text search (page + snippet), go-to-page.
  • No-TOC fallback: the user's bookmarks become a hand-made table of contents.
▶🕯️ Focus
  • Minimal by default — chrome auto-fades while reading.
  • Focus Mode: one gesture to fullscreen immersion; Esc exits.
  • Rejected for v1: timers, streaks, stats.

06 Build roadmap

Each milestone is independently usable. Build M0→M4 heads-down, hit the dogfood line, then let real reading set priorities.

M0

Walking skeleton

pdfjs-dist renders one page to canvas. The hard part, proven.

M1

Reading core

Paginate (single + spread), turn pages, go-to-page, auto-resume, night mode.

M2

Your library

Drag a PDF in → IndexedDB, content-hash id, shelf, remove.

M3

Highlights

Text layer + multi-colour highlight + underline / strike, sidecar-saved.

M4

Marginalia

Margin notes on highlights + bookmarks / dog-ears.

★

Dogfood line

Read your whole library and mark it up. Start using it for real.

M5

Notebook + note objects

Notebook panel, annotation detail pages, colour filter.

M6

Navigation

Embedded TOC, full-text search, bookmark-as-TOC fallback.

M7

Immersion + safety

Focus Mode, auto-fading chrome, export / import annotations.

07 Deferred — the "later" pile

  • OCR for scanned books
  • Freehand ink annotation
  • Tags → note-to-note linking (Zettelkasten)
  • Markdown / Obsidian export
  • Cross-library note search
  • Backend + accounts + sync
  • Gamification, done thoughtfully
  • Native tablet app
